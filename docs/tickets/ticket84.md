## Problem / goal

Remove a probabilistic test failure caused by rejecting a valid URL-safe token prefix.

## Current repo state

The invitation implementation uses Python's cryptographically secure
`secrets.token_urlsafe(24)`. Its URL-safe alphabet includes `_`, but the existing
test rejected every token beginning with that valid character. Post-merge CI
encountered that case and failed one of 204 tests.

## Research / references used

- Python `secrets.token_urlsafe` returns Base64 URL-safe text.
- The URL-safe Base64 alphabet permits letters, digits, `-`, and `_`.
- Twenty-four random bytes encode to 32 characters without padding.
